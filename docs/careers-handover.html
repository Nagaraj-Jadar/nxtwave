Careers Handover Guide

Managing open roles, applications, Resend email delivery, and Vercel deployment.

Current setup: Career roles are managed in code through data/jobs.ts. Applications are submitted through the existing form and sent by the Next.js API route at /api/careers.

1. Managing Career Roles

All open roles are stored in data/jobs.ts. There is currently no CMS or admin dashboard. Role updates require editing the file and deploying the project.

Add a role

Add a new object inside the jobs array:

{
  slug: 'design-verification-engineer',
  domain: 'Design Verification',
  title: 'Design Verification (DV) Engineer',
  jobType: 'Full-time',
  serviceId: 'design-verification',
  aboutRole: 'Role introduction goes here.',
  whatYoullDo: ['Responsibility one.', 'Responsibility two.'],
  requiredSkills: ['Required skill.'],
  goodToHave: ['Preferred skill.'],
  educationalQualification: 'Educational qualification.',
  whatWeLookFor: ['What we look for.'],
  whatYouWillWorkOn: ['SystemVerilog', 'UVM'],
  closingStatement: 'Closing statement.'
}

Required role fields

FieldPurpose
slugUnique lowercase URL identifier, for example verification-engineer.
titleRole title shown to candidates.
domainOfficial domain classification and display information.
serviceIdConnects the role to the Services filter. Use an existing ID from lib/site.ts.
jobTypeEmployment type supplied by the job description.
aboutRole, educationalQualification, closingStatementCandidate-facing role content.
whatYoullDo, requiredSkills, goodToHave, whatWeLookFor, whatYouWillWorkOnArrays of candidate-facing content.

Edit a role

Find the role in data/jobs.ts and update the required fields. Avoid changing the slug unless the URL should change. A changed slug creates a new URL and invalidates the old one.

Delete a role

Remove the complete role object from the jobs array. The role will disappear from the listing and its old URL will return a 404 after deployment. Check whether the old URL is externally shared or indexed before deleting it.

2. Role URLs and Filters

Role pages are generated automatically by app/careers/[slug]/page.tsx:

/careers/<slug>

The Careers listing filters by:

  • Domain: based on serviceId, with labels from lib/site.ts.

Use only service IDs already defined in lib/site.ts, such as design-verification, physical-design, or analog-mixed-signal.

3. Application and Email Flow

The application form is included automatically on each role page. It submits multipart form data to:

/api/careers

The API reads the server-only environment variables below and sends the application through Resend.

Environment variablePurpose
RESEND_API_KEYPrivate Resend API key. Never expose or commit it.
RESEND_FROM_EMAILVerified sender, currently careers@nxtwavesemi.com.
CAREERS_RECIPIENT_EMAILApplication recipient, currently info@nxtwavesemiconductor.com.
Security: Never put the real API key in .env.example, frontend code, Git, screenshots, or chat. Use local .env.local or Vercel Environment Variables only.

4. Local Development

Create a local .env.local file with private values, then restart the development server:

RESEND_API_KEY=your_private_resend_api_key
RESEND_FROM_EMAIL=careers@nxtwavesemi.com
CAREERS_RECIPIENT_EMAIL=info@nxtwavesemiconductor.com
pnpm dev

Test a role page, complete the form, and upload a real PDF, DOC, or DOCX resume under 10 MB. The local API returns an error when required environment variables are missing.

5. Vercel Deployment

  1. Open the correct Vercel project.
  2. Open Settings → Environment Variables.
  3. Add RESEND_API_KEY, RESEND_FROM_EMAIL, and CAREERS_RECIPIENT_EMAIL.
  4. Configure Production variables for the live site.
  5. Configure Preview variables separately if preview testing is required.
  6. Redeploy after adding or changing environment variables.

Environment changes do not automatically update an already deployed build.

6. Resend Delivery Verification

The API reports success only when Resend returns a valid email ID. The server logs:

  • Whether each required environment variable is present.
  • Safe request context such as role and resume size.
  • Resend error name, message, and status code when sending fails.
  • The Resend email ID when accepted.

After a real submission, copy the email ID from Vercel logs and check it in Resend. Confirm whether the status is queued, sent, delivered, bounced, failed, or suppressed.

If Resend reports delivered but the recipient cannot find the message, check spam, quarantine, mailbox rules, and recipient mail-server filtering.

7. Safe Update Procedure

  1. Create a branch for the role update.
  2. Edit only data/jobs.ts.
  3. Check the slug is unique.
  4. Check the service ID exists in lib/site.ts.
  5. Run pnpm exec tsc --noEmit.
  6. Run pnpm build.
  7. Run pnpm dev and test the Careers listing, filters, role URL, and application form.
  8. Commit, push, review, and deploy.
